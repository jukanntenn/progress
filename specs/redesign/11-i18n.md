# 11 · i18n(国际化)

## 决策:stdlib gettext + ContextVar + Babel 提取,多目录 locales

后端 i18n 用 stdlib `gettext` + `ContextVar`(async per-request locale 切换)+ **Babel** 提取;locales 拆到各业务应用包(Django app 式)。

## 选型理由(对比 Django/Flask/FastAPI 后社区共识)

| 框架 | i18n 机制 | per-request 切换 | 提取工具 | lazy |
|---|---|---|---|---|
| Django | stdlib gettext 封装 | thread-local(旧) | makemessages(封装 GNU gettext/pybabel) | ✅ `gettext_lazy` |
| Flask | stdlib gettext(Flask-Babel 包装) | thread-local | flask babel(封装 pybabel) | ✅ |
| FastAPI | **无内置** | 需自建 **ContextVar**(async 必需) | 无 | 无 |
| **我们** | stdlib gettext + ContextVar + Babel | **ContextVar**(async 正解) | **pybabel**(Babel) | ❌ 不用 |

**我们方案是 async FastAPI 项目的最佳实践**:
- 与 Django/Flask 同源(都基于 stdlib gettext + pybabel 提取)。
- **ContextVar 优于它们的 thread-local**(async 正解——thread-local 在 async 多协程共一线程会串)。
- **不用 lazy**(我们无 Django 的 import 时求值需求——所有 `_()` 在函数体内运行时调用,已 activate;当前 `gettext_lazy`/`_LazyString` 零调用是死代码,删)。
- **保留并实现 `ngettext`/`pgettext`/`npgettext`**(复数与上下文消歧必需;镜像 stdlib `gettext` + Django `trans_real` 契约)。spec 11 早期草案曾因"零调用"误删 `ngettext`,与第 26 行"gettext+ngettext 足够"自相矛盾;模板中 `{{ commit_count }} {{ _("commits") }}` 在 `count==1` 时输出"1 commits"语法错误,佐证复数支持必需。
- 引入 Babel 修目录漂移(与 Flask-Babel 底层一致)。

### 否掉的方案

| 方案 | 否掉理由 |
|---|---|
| Fluent(Mozilla) | 场景不需要其表达力(性别/复杂形态);gettext+ngettext 足够;Fluent 生态小众、Jinja2 集成不如 gettext |
| flufl.i18n | 额外依赖,功能当前 ContextVar wrapper 已覆盖 |
| python-i18n | 旧命名,无优势 |

## 保留 stdlib gettext + ContextVar(核心正确)

精简当前 227 行手写 wrapper:
- **删死代码**:`gettext_lazy`/`_LazyString`(零调用,~40 行)。**保留** `ngettext`/`pgettext`/`npgettext`(复数与上下文消歧必需,见上)。
- **修 `_override_stack` 共享 mutable default**:用 `default=None` + 惰性创建。
- **修 locale 缓存吞异常**:`_load_translation` 区分"文件不存在"(正常回退)与"解析错误"(上抛),不永久缓存失败。

## Babel 提取(修目录漂移病根)

新增 `babel.cfg`(根目录):
```ini
[python: **.py]
[jinja2: **/templates/**.j2]
encoding = utf-8
```

### 工作流

```
pybabel extract -F babel.cfg -o locales/progress.pot .     # 扫所有 _()/gettext()/模板 {% trans %}
pybabel update -i progress.pot -d <package>/locales -l zh_Hans   # 合并新 msgid 进 .po(标 fuzzy 待译)
pybabel compile -d <package>/locales                        # 生成 .mo
```

- `pybabel extract` 的 `DEFAULT_KEYWORDS` 含 `_`/`gettext`/`ngettext`(`babel/messages/frontend.py:897`),零配置提取。
- **CI 检查**:提取后的 .pot 与代码同步——杜绝漂移(当前病根:42 条 .po vs 63 处 `_()` 调用,21 处缺翻译)。

## locales 多目录(Django app 式,呼应 01)

locales 拆到各业务应用包,自包含:

```
src/progress/
├── locales/                    # 核心翻译(根级)
│   └── zh-hans/LC_MESSAGES/
├── cli/reports/locales/        # reports 包自己的翻译
├── cli/notifications/locales/  # notifications 包自己的
├── integrations/repo/locales/  # 各 integration 自带
├── integrations/changelog/locales/
├── integrations/proposal/locales/
└── api/locales/                # API 错误消息等
```

- Babel 多目录提取(源码核实 `babel/messages/extract.py:154` `extract_from_dir` 支持任意目录 + 映射)。
- `babel.cfg` 为每个包配提取规则。
- 每个包的翻译自治。

## locale code 统一 BCP-47 小写

- 前端 `zh-Hans` → 统一 **`zh-hans`**(小写)。
- 理由:HTTP `Accept-Language`/JS APIs(`navigator.language`)返回小写;cookie/URL 值常被浏览器/代理小写;统一小写避免 lookup 失败。
- 文件名/目录名/locale code 全用小写。

## 前后端 i18n 独立栈

- 后端:gettext 给报告/通知/日志文本。
- 前端:react-i18next 给 UI 文本(见 13)。
- **不共享翻译**(后端 .po / 前端 .json,各自维护)。
- 协调点:locale code 统一小写(上)。

## Jinja2 模板 i18n 策略

当前模板多用变量传入已翻译文本(Python 层 `_()`)。**不启用模板内 `{% trans %}`**(避免增加复杂度),翻译在 Python 层完成,模板只渲染已翻译变量。

若未来需模板内翻译,`jinja2.ext.babel_extract` 支持(在 babel.cfg 加 `[jinja2: ...]` 段),但当前不启用。

## 测试 locale 切换

保留 ContextVar `override(language)` 用于测试(当前已有,正确):

```python
with override("zh-hans"):
    assert _("Hello") == "你好"
```

## 删除清单

| 删除 | 理由 |
|---|---|
| `gettext_lazy`/`_LazyString`(零调用) | 死代码 |

`ngettext`/`pgettext`/`npgettext` **不在删除清单**——复数与上下文消歧必需。模板内联计数(如 `{{ commit_count }} {{ ngettext("commit","commits",n) }}`)依赖之;Babel 的 `DEFAULT_KEYWORDS` 已内置提取规则(`ngettext: (1,2)`、`pgettext: ((1,'c'),2)`、`npgettext: ((1,'c'),2,3)`),`pybabel extract` 零配置生成 `msgid_plural` 条目。
| `_override_stack` 共享 mutable default | ContextVar default=None + 惰性 |
| locale 缓存宽 except Exception | 区分文件不存在 vs 解析错误 |
| 手维护 .po(无 Babel) | pybabel 提取 |
